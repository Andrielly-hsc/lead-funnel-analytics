## Description

Turn the code into an installable package with pinned dependencies.

## Steps

1. Create venv: `py -3.11 -m venv .venv`
2. Write `pyproject.toml` (PEP 621): name `lead-funnel`, `requires-python = ">=3.11"`, dependencies, optional `[dev]` extras, console script `lead-funnel = "lead_funnel.cli:main"`
3. Create `src/lead_funnel/__init__.py` with `__version__`
4. Pin exact versions with `pip-compile` into `requirements-lock.txt`
5. Document setup commands in README

## Acceptance criteria

- [ ] Fresh clone + documented commands → `lead-funnel --help` works
- [ ] All dependencies pinned to exact versions in the lock file

## Deliverables

- `pyproject.toml`
- `requirements-lock.txt`
- `src/lead_funnel/__init__.py`

## Why this matters (best practice)

`pyproject.toml` is the official standard for Python projects. Loose requirements (`pandas>=2`) declare compatibility; the lock file guarantees *reproducibility* — the same versions everywhere.

## Notes

- Build backend: `hatchling` (simple, standard, supports `src/` layout out of the box).
- Only the dependencies needed by the next features are declared (`duckdb`, `numpy`, `pandas`, `pyarrow`); others are added by the feature that needs them, so the lock file never contains unused packages.
- One lock file with runtime + dev dependencies (`requirements-lock.txt`), generated by `pip-compile`. The only platform-specific package resolved on Windows is `colorama`, which is pure Python and installs on Linux too.
- Resolved versions include **pandas 3.x** (strings use the new `str` dtype by default) and **DuckDB 2.x**.
- **Problem found:** the folder name `Portifólio` contains a non-ASCII character. Python 3.11 on Windows reads `.pth` files with the cp1252 code page, but pip writes them in UTF-8, so `import lead_funnel` failed after `pip install -e .`. Local workaround: re-encode `_editable_impl_lead_funnel.pth` as cp1252. Documented in the README; permanent options are an ASCII path or `PYTHONUTF8=1`. CI (Linux, ASCII path) is not affected.
